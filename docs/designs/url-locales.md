承認は依頼文で先に渡された。「人間の確認は不要。プランを練って確定し、実装して公開する」。この文書はその決定の記録。会議室の中身（住人、動き、JSON）は前の設計のまま。変わったのは URL の制約だけ。

## Problem Statement

公開 URL は `/notes/{slug}/` で、言語も安定した ID も持っていない。これから slug の自動生成、YouTube 型の ID、UI と記事の多言語化が入る。言語をパスに入れるべきか、ID をパスに出すかを、検索に残る形で先に固定する。

## What Makes This Cool

一つの話題が、言語ごとの扉を持つ。検索結果に出る扉は言葉（`/ja/notes/ai-tools/`）。扉の裏の身分証は11文字の ID で、RSS の guid になる。slug をあとから磨いても、同じ話題だとフィードが分かる。英語の扉は、翻訳が公開リストに入るまで存在しない。

## Constraints

- 静的書き出し（`output: 'export'`）と nginx。実行時の Accept-Language 振り分けはしない。
- 既存の `/notes/...` は 301 で `/ja/notes/...` に渡す。`/feed.xml` の購読 URL は動かさない。
- 機械翻訳を、人が公開リストに入れる前に URL として出さない。
- 自己改善ループは今は作らない。`/opt/social` が後から slug や翻訳を提案できる余地だけ残す。
- Google の案内: 言語は別 URL、サブディレクトリでよい、言語の自動リダイレクトはしない、hreflang は実在する相互参照だけ。

## Premises

1. 言語はクエリではなくパスの先頭に置く。`/ja/` は国ではなく言語。
2. 検索の正規 URL は ASCII の slug。ID は正規 URL にしない。
3. slug は公開後に凍結する。変えるなら古い slug を `aliases` に残して 301 する。
4. 公開言語は `publishedLocales` だけ。いまは `ja`。
5. `/` から `/ja/` は 302。ノートの旧 URL は 301。302 なのは、二つ目の言語が来たとき `/` を言語の入口に戻せるようにするため。
6. hreflang は公開言語が2つ以上になるまで出さない。

## Cross-Model Perspective

opencode-go/deepseek-v4.1-flash に、上記の案を攻撃させた。

賛成: サブディレクトリ、ASCII slug、旧 URL の 301、未公開言語に hreflang を出さない、フィード URL の据え置き、sitemap は正規 URL だけ。

最強の反論: ID を noindex の短縮 URL に置くと、共有された評価が捨てられる。slug を正規 URL にするなら、公開時に凍結し、変更は 301 だけ、と先に決めないと安定しない。

採用した差分: `/p/{id}/` は作らない。ID は guid 専用。slug 凍結を今週のスキーマに入れる。`/` の 301 は、二つ目の言語を足すときに最上位 URL が張り付く、という失敗モードがあるので 302 にした。

## Approaches Considered

### Approach A: 日本語はプレフィックスなし
`/notes/ai-tools/` を正規のままにし、英語だけ `/en/` を足す。移行はゼロ。デフォルト言語がコードの特別扱いになり、social の書き出しが分岐する。

### Approach B: `/ja/` を正規 URL にする
全ページを `/ja/` の下に置く。ID はデータと guid。旧 `/notes/` は 301。`/` は 302。hreflang は二つ目の言語まで出さない。

### Approach C: ID をパスに出す
`/ja/notes/{id}/{slug}`。ID が正規 URL の一部になり、slug は飾りになる。共有と検索の URL が ID 寄りになり、言葉が弱くなる。

## Recommended Approach

Approach B。検索結果に残したいのは言葉で、翻訳同士を結ぶ鍵は ID。ID はパスに出さない。`/p/{id}/` もまだ出さない。共有の短縮 URL が要るときは、そのとき 301 で正規 URL に渡す。

公開パス:

- `/ja/`
- `/ja/notes/`
- `/ja/notes/{slug}/`
- `/ja/notes/tag/{tag}/`
- `/feed.xml`（item の link は正規 URL、guid は `tag:daaquan.com,2026:{id}`）
- `/sitemap.xml`（正規 URL だけ）

`id` は `[0-9A-Za-z]{11}`。ファイル名は今までどおり slug。

## Open Questions

- 二つ目の言語が来たとき、`/` を言語選択の 200 にするか、`/ja/` への 302 のまま x-default を日本語にするか。今は 302 のまま残せる。
- 翻訳を `publishedLocales` に足す前に、誰が読むか。公開ゲートは social 側。このサイトはリストに無い言語の URL を作らない。

## Success Criteria

- `https://daaquan.com/ja/notes/ai-tools/` が 200 で、canonical が自分自身、`html lang="ja"`。
- `/notes/ai-tools/` が 301 で `/ja/notes/ai-tools/` に着く。
- `/` が 302 で `/ja/` に着く。
- sitemap に `/` と `/notes/` の loc が無い。
- フィードの guid が ID で、link が `/ja/notes/...`。
- hreflang がまだ無い。`/p/` が無い。
- ブラウザ検査と本番公開が通る。

## Distribution Plan

既存の `npm run deploy`。静的ファイルに加え、nginx の言語リダイレクトを同じ公開で入れる。検証に失敗したら直前の設定とリリースに戻す。

## Next Steps

1. 話題 JSON に `id` と `locale` を足し、ルートを `app/[locale]` に移す。
2. 旧 URL の 301 と `/` の 302 を nginx と静的 HTML の両方に置く。
3. 公開して、リダイレクトと canonical を本番で見る。

## The Assignment

英語にする話題を一つだけ選ぶ。その slug はタイトルの直訳ではなく、検索される英語の言い方でメモする。ファイルにはまだ足さない。足すのは `publishedLocales` に `en` を入れるときだけ。

## What I noticed about how you think

- 「slug 生成は自動化ができたり、またはユニークな連番以外の id を作ったりしていいかな」と、検索用の言葉と安定した身分証を分けて聞いていた。
- 「url 設計に言語が含まれたほうがいいか」を、UI の翻訳と記事の翻訳が別々にできる前提で見ていた。
- 「ふだんの改善やコンテンツ運用は将来的に /opt/social に任せたり」と、今のサイトにループを埋め込まず、後から渡せる形を先に置いていた。
- 「今すぐ実装しないですが心かけておいてください」と、自己改善は余地だけ残す、と自分で線を引いていた。
